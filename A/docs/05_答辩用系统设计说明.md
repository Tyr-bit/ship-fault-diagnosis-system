# 05 系统设计说明

## 一、A 模块
A 模块：
1. 当前正式图谱在 Neo4j 中的维护与更新
2. 故障树 / 知识图谱的层层递进展示逻辑
3. 多轮对话后的结构化知识写回
4. 图谱节点和关系的人工增删改
5. 给前端提供统一接口

## 二、系统整体流程
用户提问
-> LLM + GraphRAG 检索图谱
-> 返回诊断结果
-> 用户点击“确认修复”
-> LLM 生成结构化 JSON
-> 前端把 JSON 发给 /graph/update
-> 后端把 graph_updates 转成 Cypher
-> 写入 Neo4j
-> 形成 MaintenanceCase 案例存档
-> 图谱自学习更新

## 三、创新点
1. 把正式知识图谱按故障树方式组织展示
2. 支持从故障现象逐层追溯到原因、诊断和维修
3. 支持经验确认后的自动知识写回
4. 支持人工增删改，保证图谱可持续维护

## 四、为什么这样设计
因为当前正式图谱已经有明确的节点和关系结构，所以不需要另起一套故障树模型，直接在图谱之上做“树形递进展示”和“路径查询”即可，这样前端和后端的结构是统一的，后续维护成本更低。
